# v2.0.1

Palworld Server Panel 2.0.1 是一次更新可靠性和 Docker 安全边界修复版本。重点解决 SteamCMD 因过期或损坏 manifest 反复更新失败，以及更新中断后无法自动续传的问题。

同一版本还合入了在线玩家查询与 RCON 通信的改造。这部分此前没有单独的发布说明，一并记录在下文「同版本包含的其他改进」里。

## Highlights

- SteamCMD 固定使用 TCP 模式，降低连接 Steam CM 时长时间卡住的概率。
- 单次 SteamCMD 操作增加 30 分钟超时，失败后继续按配置重试。
- 检测到 `StateFlags=6`、`UpdateResult=6` 或日志中的 `Access Denied` 时，自动备份旧 manifest 并重新获取当前版本。
- 更新过程中容器或服务器异常重启后，可根据非完整 manifest 和断点下载目录自动续传。
- 面板仍会验证目标 depot manifest，并等待游戏进程和 RCON 恢复后才将更新标记为完成。
- Docker 面板端口默认只绑定 `127.0.0.1`，避免绕过可信反向代理直接访问无登录面板。
- 修正文档中关于面板访问方式和 Docker 游戏更新行为的过时描述。

## 同版本包含的其他改进

### REST 优先的在线玩家列表

- 启用后，面板优先通过 Palworld 自带的 REST API 读取结构化玩家数据：名称、账号名、Player ID、等级和 Ping。**玩家 IP 不会返回给浏览器。**
- REST 返回空列表时如实显示 `0 人`，不会被误判成 RCON 失败。
- REST 不可用时回退到 RCON `ShowPlayers`，页面会标注数据来源：`REST API`、`RCON 回退` 或 `不可用`。
- 查询结果缓存 8 秒（可用 `PLAYER_CACHE_TTL_SECONDS` 调整），避免面板定时刷新反复打游戏服务端。
- 只有在游戏内开启玩家列表（`bShowPlayerList=True`）时才会走 RCON 回退——那是 Palworld 自己的开关，关掉时 RCON 本来也拿不到列表。

REST 默认关闭，现有部署不受影响。开启前先注意一点：面板的 `PALWORLD_REST_ENABLED` 和游戏侧的 `RESTAPIEnabled` 是两个独立开关，必须同时打开。两种部署方式的操作不同。

Docker 部署只要设面板侧变量，游戏容器启动时会把 `RESTAPIEnabled=True` 和端口一起写进 `PalWorldSettings.ini`：

```env
# .env
PALWORLD_REST_ENABLED=true
PALWORLD_REST_PORT=8212
PALWORLD_REST_PATH=/v1/api/players
PALWORLD_REST_USERNAME=admin
# 留空时复用 RCON_PASSWORD
PALWORLD_REST_PASSWORD=
```

改完要重建容器（`restart` 不会重新读取 `.env`），在线玩家会短暂掉线：

```bash
docker compose up -d palworld
```

systemd 部署没有这个自动化，需要两步：先在游戏侧开启 REST（面板「配置」页勾选 `RESTAPIEnabled`，或直接改 `PalWorldSettings.ini`），再在 `/etc/palworld-panel.env` 里写同样的 `PALWORLD_REST_*` 变量并重启面板服务。只做其中一步，面板只会一直报「连不上」。

`8212/tcp` 只应由同机或 Compose 内部网络访问。Docker 部署下不要在 `docker-compose.yml` 里加 `8212:8212`：这个接口走 Basic Auth，映射到宿主机等于把管理员凭据暴露在公网上等人爆破。

### RCON 响应处理

- 重写响应读取逻辑，兼容 Palworld 的两种非常规行为：不返回传统 Source RCON 完成哨兵，以及响应包 ID 固定为 `0` 而不是回显请求 ID。旧实现会把这类正常响应当成错误或直接超时。
- 多包响应按统一截止时间聚合，服务端在响应发完后主动断开连接不再被判定为失败。
- 面板与后台更新脚本共用同一份 `rcon.py`，两套实现不会再各自漂移。

### 部署管理字段保护

`PublicPort`、`QueryPort`、`RCONPort`、`RCONEnabled`、`AdminPassword` 由部署配置统一管理，现在：

- 不再出现在配置接口的返回里；
- 无法通过通用配置表单提交修改；
- 保存其他字段时保留原值，不会因为表单里缺这几个键而被清空。

这条是防事故用的：面板侧的 RCON 凭据一旦和游戏内的 `AdminPassword` 漂移，RCON 控制台会失效，停止服务器前的 `Save` 也会认证失败。

## Upgrade Notes

Docker 用户：

```bash
git pull
docker compose up -d --build
```

不要使用 `.env.example` 覆盖现有 `.env`。如需调整 SteamCMD 网络策略，可以在 `.env` 中设置：

```env
# auto、direct 或 proxy
STEAMCMD_NETWORK_MODE=auto
```

面板现在默认监听 `127.0.0.1:8080`。如果此前直接通过 `http://服务器IP:8080` 访问，请配置同机 Nginx/Caddy、SSH 隧道或可信私有网络入口。

systemd 用户可以正常升级面板代码，但本版本的 SteamCMD manifest 自动修复和中断续传主要针对 Docker Compose 后端：

```bash
git pull
sudo bash install.sh
sudo systemctl restart palworld-panel.service
```

## Recovery Behavior

自动修复只处理 SteamCMD 应用状态和对应临时下载目录：

- 旧 `appmanifest_2394010.acf` 会重命名为带 UTC 时间戳的 `.stale-*` 备份。
- 只清理应用 `2394010` 的 `steamapps/downloading` 和 `steamapps/temp` 临时目录。
- 不删除 `Pal/Saved`、世界存档、玩家存档或服务器配置。
- 已完成的 manifest 状态为 `StateFlags=4`，普通容器重启不会重复连接 Steam 或重新下载。
